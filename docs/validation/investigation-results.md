## Performance qualification

The measurement files retain all samples, source SHA-256 values, host metadata and method. The [initial continuation series](../architecture/experiments/investigation-initial-results.json) and [pre-Unicode-fix series](../architecture/experiments/investigation-pre-unicode-results.json) remain available. The final series is [investigation-results.json](../architecture/experiments/investigation-results.json), generated by:

```sh
python docs/architecture/experiments/qualify_investigation.py
```

Five alternating, sequential fresh processes run each workload. Cache/scheduling on this shared host are uncontrolled. Script wall time begins after imports; `process_wall_seconds` in the final series also includes interpreter startup. Memory is each process's reported peak RSS, not aggregate simultaneous parent+worker resident memory. Worker `ru_maxrss` can include the fork baseline. No other benchmark job runs concurrently. The runner verifies unchanged source hashes after every sample.

| 20,000 Jetsam rows; 2,000-event snapshot + two mock investigations | 5.514–5.715 / 5.597 | 123,740 | 7 steps, complete; 18,000 omissions disclosed |

All completed report pairs were byte-identical within their case. New diagnostic runs also checked unchanged source state; each investigation separately reverified original bytes. A fresh case has fresh IDs/import metadata, so cross-case whole-report hashes are not expected to match.

The capacity probe imports 20,000 Jetsam process rows but deliberately gives the investigator the default earliest 2,000-event snapshot. Its 18,000 omissions are reported; it does not demonstrate full 20,000-event model analysis, complete device history or correct malware detection. The 32-report workload exercises the complete recurrence/hypothesis workflow. Its 200,000-unit token-estimate budget is recorded in the benchmark source; the normal default remains 131,072.

Current gate: a bounded local five-run qualification against 10 seconds/256 MiB, not a general scalability guarantee. Earlier core/privacy timing failures remain in ADR-001 and their original data. Improvements versus those runs cannot be attributed to a code optimization: host scheduling/runtime conditions changed and no controlled speedup experiment was performed. Indexed storage, hostile worst-case memory, sustained acquisition, named reference hardware and native comparisons remain open.
