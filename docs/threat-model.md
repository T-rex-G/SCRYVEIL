# Threat model — offline core and optional investigation

Assets: original bytes and source locations; consent scope; private identifiers/credentials; honest observations and uncertainty; owner machine. All evidence strings, filenames, tool results and model responses are untrusted. The owner supervisor, installed package, interpreter/native libraries, libseccomp and kernel are trusted. No defense against root or a hostile same-UID process controlling the parent is claimed. Acquisition remains unsupported. Network egress is disabled by default; only the explicitly configured provider broker can open an authorized connection.

| Threat | Implemented control / executable evidence | Residual risk |
|---|---|---|
| Archive traversal, links, bombs | No extraction; unsupported input refused; regular file and path checks; explicit IPS size/depth/node/process bounds | Parent-directory races not fully hardened; JSON parser is in trusted owner process; no claim of safe archive ingestion |
| Resource exhaustion | Case 8 MiB/file, 32 artifacts/20k events/64 MiB state; IPS depth 32/100k nodes; snapshot 16 MiB; 64 KiB actions/results; query and request limits; worker CPU/address-space limits and parent deadlines | Whole-state serialization; no hostile worst-case memory proof for parent; context/token estimates are not billing guarantees |
| Forged provenance/detector output | Original hashes, reparse comparison, stored-analysis recomputation, exact locators and post-investigation state digest; existing tamper tests | Local audit can be entirely rewritten by trusted identity; no signed acquisition/external custody anchor |
| Prompt injection in logs, filenames or diagnostic strings | Strings remain JSON data; fixed action and argument schemas; no model-driven imports/eval/shell; forbidden calls rejected even after injected artifacts are queried | Models can still form misleading hypotheses or waste allowed queries; semantic prompt injection is not solved |
| Tool-response poisoning / fabricated references | Supervisor-created snapshot; bounded replies; exact field/type equality and case-bound IDs; only queried deterministic measurements accepted | Compromised trusted package/parent is out of scope; a malicious source can itself lie; reference validity does not prove causal entailment |
| Secret disclosure / unrelated file reads | Investigator receives no credentials or paths; cleared environment, closed inherited descriptors, no file-open syscalls; actual open/read/write/unlink denial tests | Selected provider broker must hold its one credential in memory; OS/user compromise or the approved provider can expose it |
| Unauthorized execution or new network access | Worker syscall allowlist denies socket/connect/fork/exec/ptrace; no acquisition, messaging, browsing or plugin tools; actual OS probe | Kernel/native runtime flaws remain possible; seccomp is one boundary, not a complete universal sandbox |
| Cross-case requests / path arguments | Single immutable in-memory case snapshot, no case-switch parameter, strict closed schemas, foreign event IDs rejected; actual second-case test | Humans with the same UID retain owner-level access outside the investigator |
| Remote exfiltration / malicious destination | No network by default; exact disclosure digest before credential read/provider use; changed case/question/endpoint/options/budgets rejected; public-address DNS pinning, TLS hostname verification, no redirects/proxies | Explicitly approved evidence does leave the host; provider retention/secondary disclosure cannot be controlled here; local server could forward unless independently offline |
| Compromised model/provider | Provider bytes parsed after broker policy, including TLS handshake; no response-driven tool routing outside allowlist; bounded JSON and fixed errors; HTTP/TLS failure tests | Actual external providers not tested; TLS trust store and server identity do not establish good provider conduct |
| Infinite loops / cancellation / failures | Max 32 requests, action/context/response bounds, wall timeout, kill/reap in finally; mocked cancellation and real transport timeout tests | No automatic resumable checkpoint; cancellation before worker startup returns a fixed error, not a partial trace |
| Misleading threat intelligence | Exact user-supplied domain indicators remain labeled; no automatic download or external research tool; hypotheses unresolved | No STIX, freshness, signed feed validation, calibrated false-positive/negative rates or independent attribution |
| Case/report exposure in CI | Only fictional allowlisted fixtures; no evidence upload artifacts; default identifier minimization; hygiene scanner | Scanner is heuristic; report metadata and model text remain sensitive; shell redirection permissions are the owner's responsibility |
| Concurrent writers / interruption | Cooperative locks, atomic metadata replace/fsync, source revalidation before/after; investigator never saves into case | Crash can leave unreferenced original/temp files; no complete recovery UI; external modifications cause failure |
| Supply chain | Zero third-party Python runtime packages, fixed internal subprocess modules, pinned dev versions/action SHAs; system library used rather than bundled | No wheel hashes in lock; native dependencies trusted; no full transitive audit; dynamic libseccomp distribution obligations remain relevant |

The tested invariant is that encountering untrusted content does not expand the investigative worker's permissions. Adversarial tests check this at the tool boundary and with kernel-denied operations. They do not measure a real LLM's resistance to persuasion or prove malware-detection accuracy. The user may explicitly authorize development changes; that does not grant the product's runtime investigator write access.

Future collectors and archive/native parsers need separate identities/handles, declared side effects, bounded output, acquisition consent and independently validated formats. A subprocess by itself, or a change of language, does not supply those controls. See [ADR-002](architecture/ADR-002-read-only-ai-investigation.md) for the concrete current boundary and simpler alternatives considered.
