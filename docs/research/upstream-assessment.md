## Concrete source findings and design consequences

1. Shutdown process lines do not themselves establish an accurate individual execution time. iLEAPP binds them to the following SIGTERM epoch, preserves trailing entries with null time, separates process rows from reboot rows and marks suspicious directories as leads only. Its EOF tests check unchanged bytes, missing timestamp, cross-file isolation, duplicate behavior and AppleDouble exclusion. SCRYVEIL should retain unknown times, never interpolate a reboot and never call a path alone spyware.
2. SAF parses `system_logs.logarchive/Extra/shutdown*.log`, while MVT filesystem discovery targets `private/var/db/diagnostics/shutdown*.log`. These are distinct acquisition locations of related content; importing both is not independent corroboration. Preserve physical artifact hashes and record duplicate lineage.
3. MVT shutdown matching includes exact path/process IOC context. Its README explicitly states no public IOC match does not mean a clean device. SCRYVEIL should not ship old copied indicators or infer confidence from unmatched public datasets.
4. PMD3 pcapd packets include pid/comm and effective pid/name plus interface and seconds/microseconds. write_to_pcap uses device timestamp when available, host clock otherwise. A future SCRYVEIL importer must preserve the time-source distinction and cannot infer process identity from a generic PCAP. No arbitrary TLS payload decryption or remote-operator attribution follows.
5. PMD3 transport code returns `userspace` by default; a stale nearby comment still mentions macOS native default, so behavior was checked in the actual default_transport_preference function. On pre17.4 it catches UserspaceTunnelUnavailableError and tries native macOS or tunneld. This does not imply every service works on every version. Discovery uses autopair=False but selected-device establishment may pair; owner consent required before invoking it.
6. PMD3 tunnel guide warns non-loopback tunneld HTTP access is unauthenticated. SCRYVEIL must never expose a remote device-control server as a convenience feature.
7. iLEAPP PrivacyAccounting SEGB records can carry unknown kind semantics and deleted/zeroed payloads; old surviving timestamps do not prove old accesses. Source notes explicitly distinguish observed format from unverified semantics. This reinforces unknown-state records in the original core.

## Experimental APR format evidence

An additional inspected source is [phonecheck/privacy_report.py](https://github.com/shoshiiiin/iphone-tracker-check/blob/8c34c6b52e9870424cf724af9f2ec755da495226/phonecheck/privacy_report.py) at current SHA `8c34c6b52e9870424cf724af9f2ec755da495226`.

- `type=access`: category, accessor.identifier, timeStamp, kind `intervalBegin` / `intervalEnd`, identifier session correlation.
- `type=networkActivity`: bundleID, domain, hits. The inspected function **aggregates** hits by app/domain and supplies no packet interval series. Preserve it as network summary; exclude from periodicity detector.
- The upstream parser accepts JSON or NDJSON and silently skips invalid lines. SCRYVEIL should reject or record line-specific failures, never silently discard them.
- Its sensor function closes unended intervals at the latest timestamp of another event. Do not copy that inference: retain open-ended interval uncertainty.
- This is third-party source-format corroboration, not an Apple normative schema or real Apple-export fixture. Mark SCRYVEIL APR parser experimental with exact supported shapes and no hardware/version certification.
- A single-file original shutdown.log parser is an alternative well-grounded portable export if APR validation proves too uncertain.

## Consequential source findings

### App Privacy Report schema boundary

The reader and its synthetic tests support access records with `type=access`, `category`, `kind=intervalBegin|intervalEnd`, `identifier`, `accessor.identifier`, `timeStamp` ISO-offset string. Network records use `type=networkActivity`, `bundleID`, `domain`, and aggregated positive `hits`. The inspected implementation does not establish per-hit timestamps. Never expand hit counts into imaginary connection events; do not run periodicity on aggregate counts. Missing access-session ends must remain unknown, not extrapolate to a different app's last record as this upstream does. Its `_time` assumes UTC when absent; SCRYVEIL should reject or explicitly mark unknown offset. Its loader silently drops invalid JSON lines; preserve parser failures in coverage. No actual Apple-generated export was obtained or tested, so matching this shape warrants experimental status only, until Apple documentation/real sanitized format fixtures corroborate it.

### Read-only must be checked at service/flag level

`idevicecrashreport` initializes `keep_crash_reports=0`; after copying it calls `afc_remove_path` unless `--keep`. Even with keep enabled, it starts `com.apple.crashreportmover` to move logs on the device, then `com.apple.crashreportcopymobile`. Thus a generic crash acquisition adapter cannot truthfully promise no device state changes. No such calls were executed in this research.

### Heuristic boundaries

iShutdown counts delay phrases before SIGTERM and flags paths, not a calibrated compromise probability. Its parser assigns reboot epochs to preceding process records; that is an association with reboot, not necessarily each process event's exact observation timestamp. Triangle Check uses known BackupAgent marker and co-occurrence of filesystem/network/location signals; code comment says one minute but actual `time_delta_max=60*5` is five minutes. Its `range(len(expanded_timeline)-events_max)` excludes short timelines/last candidate positions; no runtime failure or exploit reproduced. Network regularity uses median absolute deviation and short intervals; legitimate push/cloud sync remain competing explanations. The tracker example suppresses whole Apple address ranges/DNS names, which cannot certify activity safe.
